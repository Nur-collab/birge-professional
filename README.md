# Birge — professional working copy

This directory is a clean working copy of the Birge project. The original
`../birge` and `../birge-backend` directories are intentionally left untouched.

```
birge-professional/
├── birge/            # React + Vite PWA (frontend)
├── birge-backend/    # FastAPI + SQLAlchemy API
└── .github/          # CI
```

## Requirements

- Node.js 20.19+
- Python 3.10+
- PostgreSQL for production; SQLite is supported for local development and tests

## Local setup

### Backend

```bash
cd birge-backend
python -m venv venv
# Windows: venv\Scripts\activate
# Linux/macOS: source venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt
cp .env.example .env          # fill the values locally; never commit .env
alembic upgrade head          # create/update the local schema
uvicorn main:app --reload --port 8000
```

For local Redis-backed tests (Docker required):

```bash
docker compose up -d redis
cd birge-backend
TEST_REDIS_URL=redis://localhost:6379/0 ./venv/Scripts/python.exe -m pytest -q
```

The API is available at `http://127.0.0.1:8000`. Interactive docs:
`http://127.0.0.1:8000/docs`. Operational probes: `GET /health` (liveness)
and `GET /ready` (database and optional Redis). HTTP responses include
`X-Request-ID`.

### Frontend

```bash
cd birge
npm ci
# Only for local development. Vite loads .env.local in production too,
# so never put the local API URL there.
cp .env.example .env.development.local    # VITE_API_URL=http://127.0.0.1:8000
npm run dev
```

Production builds read `VITE_API_URL` from `.env.production` or from the
hosting provider's environment. The build fails if that value points to
`localhost`, `127.0.0.1` or `0.0.0.0`.

### OpenAPI types

`birge/openapi.json` is the committed frontend contract. After a backend
API/schema change, regenerate the declaration:

```bash
cd birge-backend
./venv/Scripts/python.exe scripts/export_openapi.py
cd ../birge
npm run api:types
```

`src/types/api.d.ts` is generated by `openapi-typescript`; `src/utils/api.js`
uses it through JSDoc. The declaration is editor-time only and does not change
the runtime bundle. CI regenerates both artifacts and fails on drift.

## Environment variables

Backend (see `birge-backend/.env.example`):

| Variable | Required | Purpose |
|---|---|---|
| `ENVIRONMENT` | production | `development`, `test` or `production` |
| `SECRET_KEY` | yes | JWT signing key; generate a long random value |
| `DATABASE_URL` | yes | PostgreSQL URL in production, SQLite locally |
| `ALLOWED_ORIGINS` | production | Comma-separated exact frontend origins |
| `TELEGRAM_BOT_TOKEN` | production | Telegram code delivery and bot |
| `TELEGRAM_WEBHOOK_SECRET` | production | Telegram webhook verification |
| `ADMIN_PHONES` | production | Comma-separated phones allowed to call admin endpoints |
| `IMGBB_API_KEY` | optional | Server-side profile photo uploads |
| `INTERNAL_SYNC_ENABLED` | no | Enables the internal Telegram sync endpoint (development only) |
| `INTERNAL_SYNC_SECRET` | with sync | Separate secret for the internal sync endpoint |
| `REDIS_URL` | production | Shared rate limits and SSE/WebSocket Pub/Sub; empty = single-process mode |
| `LOG_LEVEL` | no | Application log level (default `INFO`) |
| `LOG_JSON` | no | Force JSON logs locally; production always uses JSON |
| `SENTRY_DSN` | optional | Enables backend Sentry error monitoring; empty disables it |
| `SENTRY_ENVIRONMENT` | no | Sentry environment; defaults to `ENVIRONMENT` |
| `SENTRY_TRACES_SAMPLE_RATE` | no | Backend trace sample rate, `0`–`1` (default `0.05`) |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | no | Access token lifetime (default 60) |
| `REFRESH_TOKEN_EXPIRE_DAYS` | no | Refresh token lifetime (default 30) |

Frontend:

| Variable | Purpose |
|---|---|
| `VITE_API_URL` | API base URL (no trailing slash); production value, not `.env.local` |
| `VITE_SENTRY_DSN` | Optional browser Sentry DSN; empty disables the SDK |
| `VITE_SENTRY_ENVIRONMENT` | Optional Sentry environment; defaults to Vite mode |
| `VITE_SENTRY_RELEASE` | Optional frontend release name |

Secrets must never be committed. `.env`, `.env.*`, databases and build
artifacts are ignored by git; `.env.example` and `.env.production.example`
are templates only.

## Security and dependency checks

- Dependabot opens weekly updates for `pip`, `npm` and GitHub Actions.
- `pip-audit` runs in CI and in the scheduled Security workflow.
- Gitleaks scans commits for secrets; organization repositories need a
  `GITLEAKS_LICENSE` secret (personal repositories do not).
- Sentry is opt-in: DSNs are read from environment, PII is disabled and request
  bodies are not attached to events.

## Architecture rules

- Routers own HTTP concerns; services own business rules; models own persistence.
- All schema changes go through Alembic; do not use `create_all` in production.
- Every new endpoint needs an authorization check and a regression test.
- Do not add a dependency without a clear need and a pinned version.
- Realtime uses Redis Pub/Sub when `REDIS_URL` is set; without it, local
  in-process delivery is used for development. Use one Redis instance shared by
  all production workers.

## Deployment

- Frontend: Vercel (or another static host), `npm run build`, `dist/`.
- Vercel SPA fallback is declared in `birge/vercel.json`; keep it so deep links
  such as `/trips/42` return `index.html` instead of a 404.
- Backend web command: `uvicorn main:app --host 0.0.0.0 --port $PORT`.
- Render is configured manually in the Dashboard: root `birge-backend`,
  build `pip install -r requirements.txt`, health check `/ready`.
- Set the **Pre-Deploy Command** to `alembic upgrade head`. Use separate
  Render resources and secrets for staging. Blueprints/IaC are not used.
- Keep staging and production databases separate. Follow
  `docs/RUNBOOK.md` for PITR/logical backups and the quarterly restore drill.
